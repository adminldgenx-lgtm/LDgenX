# Scientific publishing and client workspaces — 30 October 2026

Long scientific drafts now keep navigation and saving within reach. A persistent action bar links writing, sources and publishing, shows word count/approximate reading time and the last server save in Paris, and supports ⌘/Ctrl+S for draft saving only. Formatting, figures, tables, video, revision history, translations and explicit publication retain their existing behavior.

An optional structure adds four empty scientific sections to a genuinely empty new document, in its content language. It cannot replace text, figures or videos, contains no findings and cannot satisfy the publication body requirement by itself. The publishing panel lists missing requirements before submission. Recovery validates stored data, recognizes URL-only edits and clears the scientific-review flag. Document loads ignore responses for a previously opened document. Automatic private media metadata refresh is throttled to once every thirty minutes during an active writing session or on return, with a separate manual retry; newly selected media are retained if an earlier metadata read finishes afterward. Images themselves are not uploaded again by these refreshes.

Client administration displays real status counts and supports full-name, organisation and email searches with or without accents. Suspension requires confirmation naming the client and does not delete their data or appointments; existing retention rules continue to apply. Administrator file/appointment reads provide retry controls; unavailable retention settings are distinguished from retention being disabled.

The client file screen separates received documents from attachments the client sent in messages. Both views support filename/note search and show recent files first. Failed file and appointment reads no longer remain indefinitely loading or imply an empty result. The existing server authorization, private storage, signed downloads, client isolation and active-administrator checks remain in force; this release changes no database permissions or backend schema.

The handover guide is [PRISE-EN-MAIN-LDGENX-2026-10-30.md](PRISE-EN-MAIN-LDGENX-2026-10-30.md). It explains draft → preview → review → publish, existing working copies, scientific attribution, media, client statuses and the client workspace.

Validation evidence lives in `docs/workspace-qa`. The repeatable browser journey checks real API/Data API isolation, suspension/reactivation and private draft saving; file/error views use synthetic browser fixtures. No mail, public article, uploaded file or appointment is created. Confirmed test users and private drafts are removed afterward. The CLI transport keeps credentials in stdin/pipes; safe reads retry, and fixture creation recovers ambiguous responses by its unique email. Idempotent fixture status operations can be retried without duplicating records.

The final combined unit run passed all 38 editorial, Calendar and portal tests. Nine workspace browser/API journeys passed on the local production build with no browser exception; disposable accounts and drafts were removed successfully. Mobile screenshots were visually inspected. The Calendar release separately passed 16 actual Google round-trip assertions and 14 browser flows on the production domain. Build/typecheck, lint and French typography pass; HTML verification covers 151 prerendered pages and SEO verification covers 147 indexable pages with zero errors or warnings. The local workspace result is recorded in `docs/workspace-qa/local/results.json`.

Account configuration still requires the owner: custom Auth SMTP and notification sending are not configured; Google Cloud's current Audience/publishing status is not available through the Calendar connection; staff must share/map the actual calendars that should block their availability. Google sign-in is enabled. OVH email, mail DNS, Cloudflare email protection and paid plans are not changed.
