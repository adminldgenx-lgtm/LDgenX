# Reprise Canva — 17 octobre 2026

Version locale uniquement, sans déploiement. L’état Git était propre au début de la reprise.

## Modifications

- Les catalogues `src/content/fr.ts` et `en.ts` affectent les nouvelles photos aux expertises Génomique des populations, Bioinformatique et Sélection génomique. Le parcours scientifique utilise les nouvelles photos de bioinformatique et d’aide à la décision. Les mêmes données alimentent l’accueil, les aperçus de navigation et les pages d’expertise.
- `src/sections/CustomAssay.tsx` enrichit le module existant : recherche sans distinction d’accents, noms français/anglais/scientifiques, quatre filtres, liste desktop défilante, sélection native compacte sur mobile, fiche typographique, remise à zéro, état vide et liens de contact FR/EN. La sélection reste manuelle ; seules les étapes pédagogiques conservent leur animation avec pause.
- Les étapes se parcourent aussi avec les flèches, Début et Fin. Le titre approuvé, les quatre étapes, la mention « Illustration du principe » et la précision sur la quantification de l’ADN sont conservés.
- `Photo` lit les dimensions, textes alternatifs et crédits des nouvelles photos. Le crédit HTML `@UNIMA` accompagne uniquement la nouvelle photo de crevette, dans tous ses emplacements. Les autres photos et leurs rendus conservent leur fonctionnement.
- Le hero, l’hélice, la géométrie et les contrôles de l’atlas, le parcours Artois-Picardie, les 15 publications et les routes sont conservés. Une correction locale de l’atlas efface l’état d’entrée `pending` en mouvement réduit : après hydratation, cet état pouvait laisser le paysage recadré et masquer des libellés. La géométrie et l’animation normale sont inchangées.

## Catalogue dPCR et confirmation client

`data/assay-targets.json` conserve exactement les **22 entrées sources**, leurs libellés français, la page Canva et leur provenance. `scripts/build-assay-targets.mjs` génère les données publiques FR/EN de `src/content/assay-targets.ts` et contrôle leur cohérence. `npm run check:assays` vérifie la synchronisation, les doublons, les catégories et la provenance.

**21 associations sont affichées** : 5 mammifères, 13 poissons, 1 reptile et 2 invertébrés. Aucune espèce supplémentaire n’a été déduite d’un échange ancien. La présence d’amorces et de sondes en interne est distincte de la validation, des matrices et des performances d’un test. Aucun seuil, badge « validé » ou nombre d’animaux n’est ajouté.

La seule entrée retenue en interne est **Neomys anomalus — Musaraigne de Miller**. La [publication de Querejeta et Castresana (2018)](https://doi.org/10.1002/ece3.4487), consultée pour la nomenclature, distingue *N. anomalus* et *N. milleri*. Elle ne prouve pas la cible des amorces et sondes LDgenX. Demander à la cliente **quelle espèce cible effectivement le test**, sans renommer automatiquement l’entrée historique. Cette association et les messages de confirmation sont exclus de l’interface et du bundle publics. La référence taxonomique n’a pas été ajoutée aux publications de l’équipe.

## Vérifications et reprise

Les résultats et captures sont conservés dans [qa-2026-10-17](qa-2026-10-17/README.md). Le détail des contrôles figure aussi dans `docs/VALIDATION.md`.

Commandes de contrôle :

```sh
npm run lint
npm run typecheck
npm run check:typography
npm run check:assays
npm run build
npm run check:html
node scripts/check-http.mjs http://127.0.0.1:4174
```

Le contrôle navigateur reproductible `scripts/check-assays-browser.mjs` utilise une installation existante de Playwright, via `LDGENX_PLAYWRIGHT_MODULE=/chemin/vers/playwright/index.mjs`, puis accepte l’origine de la prévisualisation en argument. Il ne modifie pas les dépendances du site.

Un débordement de l’en-tête à **320 px** est préexistant : largeur de document de 349 px, avec les polices chargées, reproduite avec le code Git d’origine dans une copie isolée. Les sections modifiées restent à 320 px ; aucun débordement observé à 390, 768 et 1440 px. Ce problème de l’en-tête est documenté séparément et n’a pas entraîné de changement global de mise en page. Aucun audit Lighthouse supplémentaire n’a été réalisé.
